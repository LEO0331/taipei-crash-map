# 內湖交通壅塞與道路廊帶決策支援 MVP

版本：1.0.0；查核日期：2026-10-21（Asia/Taipei）。[PR #7](https://github.com/LEO0331/taipei-crash-map/pull/7) 尚未合併。

目前交付的是**交通觀測資料完整性與設備涵蓋查核**。尚未取得可比較的歷史觀測，因此不發布反覆壅塞排名。本文配合[來源稽核](neihu-congestion-source-audit.md)、[方法論](neihu-congestion-methodology.md)與[交付證據](neihu-congestion-delivery.md)閱讀。

## 1. 政策問題與研究範圍

在有限交通工程調查容量下，哪些內湖科技園區候選道路、方向與通勤時段值得進一步查核？回答之前，必須先確認量測來源、設備識別、方向與期間是否可比較。

初始研究清單為瑞光路、港墘路、堤頂大道、舊宗路、民權東路、成功路、環東大道。依官方道路名稱取得 58 個設備，不等於已驗證內科研究邊界。所有設備的 `geographicScope` 都是 `unverified`；民權東路、成功路等路段可能超出內科功能範圍，不能把整條道路視為通勤系統的已驗證涵蓋。

## 2. 內湖科技園區交通壅塞背景

[交通局內科背景簡介](https://dot.gov.taipei/Content_List.aspx?n=83A9D742D585DEE7)是研究背景來源；通勤車流與道路／橋梁連接條件值得查核，但不代替本專案的速度或旅行時間量測。[TUIC 研究頁](https://tuic.gov.taipei/neihu_traffic/)本次查核仍回傳 502，無法重新核對其內容，不能聲稱已成功取用。

政府公布的改善成效有自己的期間、道路與研究設計。它們是獨立政策背景，不是這個 POC 的前後測結果，也不進入排序。

## 3. 事故分析與壅塞分析的區別

事故地圖回答歷史事故記錄在哪裡、何時發生，以及描述性分布。交通決策模組回答觀測證據是否足以支持特定設備／方向／時段的工程調查。

事故件數不是速度、流量、占有率或旅行時間。不以事故熱點推估壅塞，不把 VD 車流當作附近事故的暴露量，也不把兩者合成分數。新分頁不需要載入完整事故明細。

## 4. 官方 VD 與道路路段資料

實際保留 A–F 六個官方端點的原始檔案、SHA256 與取得時間，合計 1,710,095 bytes。A 為設備清冊、B 為舊版動態 VD、C 為道路速率快照、D 為路段清冊、E 為旅行時間、F 為偵測配對；完整資料集 ID 與端點見來源稽核。

A 的 604 個全市設備中有 58 個符合候選道路名稱。D 有 818 筆路段中繼資料，但尚無可接受的 VD LinkID 對照。目錄 CSV 可能只列介接網址，不能算作交通觀測。TDX 歷史服務未取得，沒有用退休資料集填補。

## 5. 車速、車流量、占有率及旅行時間定義

| 指標 | 可接受的解讀 | 本版狀態 |
| --- | --- | --- |
| 車速 | 特定設備／車道／取樣區間的速度；正規化契約為 km/h | 官方動態來源定義未接受，不公開觀測值 |
| 車流量 | 特定車道、設備或連結在特定區間的車輛計數 | 單位與涵蓋未確認，不合併或推估需求 |
| 占有率 | 偵測器在區間內被車輛占用的時間比例；契約為百分比 | 與流量分開，來源語義尚未接受 |
| 旅行時間 | 有明確起訖、方向及配對的路段行程時間 | E/F 為空且過時，沒有可用值 |

不把點速度轉成整條廊帶旅行時間。不用不同設備速度的簡單平均建立道路指標。不把未確認的 `TimeInterval=5` 當作已確認的秒數或分鐘數。

## 6. 偵測器與道路方向識別

優先使用官方 VD → DetectionLink → LinkID 與 RoadDirection。31 個設備各有單一連結／方向，共 31 個不同 LinkID；另 27 個多連結設備保留 `null`，不任選一個方向。

方向代碼 E、N、NE、NW、S、SW、W 沿用來源；缺值不補值。座標只支援設備位置展示，不代表功能性道路關係。沒有可驗證的道路線形，因此只畫點，不內插連續壅塞線或區域。

## 7. 歷史觀測資料可用性

B 的交換時間是 `2024/11/14T16:46:02`，沒有 UTC offset，2,195 筆車道紀錄全部排除。C 是 `2026/10/21T09:43:03` 的單一快照，時區、定義與設備對照不足。E/F 的 2024-12-18 檔案為空。

本版接受的觀測期間為 `null`，歷史日數為 0，交通表現候選為 0。沒有兩週可比較序列；這不代表歷史資料不存在，而是此次沒有取得符合條件的來源。TDX 歷史資料需要另行確認服務、權限、日期篩選、費率與配額。

## 8. 尖峰、離峰與期間可比較性

分析假設一律使用 Asia/Taipei：早峰 `[07:00,10:00)`、晚峰 `[17:00,20:00)`、離峰 `[10:00,16:00)`。區間右界不納入，避免重複計數。這些不是官方尖峰定義。

比較必須維持相同設備、LinkID、方向、日期、來源版本、中繼資料版本、車道識別／類型及取樣規格。離峰參考使用同日同設備條件；不借用其他日或其他設備的速度。週一至週五不等於已核對假日的一般工作日。本版歷史控制停用。

## 9. 資料完整性及品質

預期樣本數必須由已確認取樣間隔與完整分析窗口推算；有效完整率為有效唯一區間數／預期區間數。重複時間槽保守排除，缺漏不補成 0。

目前取樣規格、預期樣本、缺失日／區間、停機時間與歷史完整率都是 `null` 或無法評估。0 個接受觀測表示「沒有通過資格的資料」，不是 0 車速／0 車流。B 的 89 筆零速度只列稽核統計，不決定其是否壅塞或失效。

## 10. 壅塞觀測方法與假設

方法 ID：`neihu-traffic-observation-review-v1`；設定版本：`1.0.0`。

僅在來源與窗口合格時，計算同設備的尖峰速度中位數、離峰參考中位數及 `(離峰參考 − 尖峰速度) / 離峰參考`。參考值必須大於 0；負結果保留，表示尖峰速度高於參考，不默默截成 0。

此值是「相對觀測離峰參考的減速」，不是自由流壅塞指數、官方服務水準、容量比或人時延誤。時間聚合與分級函式已有合成測試，但本版沒有已接受的官方歷史聚合結果。

## 11. 調查優先順序模型

A：至少 5 個合格週一至週五、至少 3 天超過減速門檻，且這些平日的減速中位數達門檻。B：有效比較存在且至少 2 天重複達門檻，但未達 A。C：有效比較存在但沒有 A/B 訊號。證據不足：少於 2 個可比較日、完整率不足、方向或地理資格未確認等。

預設完整率 80%、相對減速 20%，皆為 POC 篩選假設。地理範圍未驗證的設備不能取得交通表現資格。品質查核分為 urgent、review、ready，與交通表現分開排序。

## 12. 查核容量與地理均衡情境

每個名額代表可能的調查工作，可選 5、10、不限或正整數。減速優先依分級、重複頻率、減速幅度與證據條件排序；廊帶平衡依穩定廊帶 ID 輪流取得各廊帶的已排序候選，是查核多樣性策略。

目前兩種交通表現情境都是空清單；不能展示假想節省時間。資料品質優先在 58 個候選中，容量 5 選出 5 筆、3 條廊帶；容量 10 選出 10 筆、5 條廊帶。具體設備清單見交付報告。

## 13. 資料品質查核模式

58 個設備均缺可比較歷史與已驗證研究範圍；27 個方向／連結待確認者屬 urgent，31 個單一方向者屬 review。品質名單的用途是確認設備對應、資料定義、時區與來源連續性。

設備缺少或停機不能當作低需求或道路暢通。所有品質候選的觀測完整率與異常率為未知，不以捏造的百分比排序。

## 14. 情境敏感度

5 對 10 的比較固定證據範圍與品質目標，只改名額。來源版本、日期、設備群、方向／連結、時段、完整率門檻與參考定義改變，必須標示不同證據範圍。品質目標不能與壅塞目標比較為同一政策成效。

90% 完整率、30% 減速與早晚峰比較的運算函式有測試；因本版沒有合格歷史值，介面明示不能估計這些敏感度影響。兩組清單相同時如實呈現。

## 15. 決策摘要及匯出

提供 JSON 與 CSV，保留政策問題、快照與來源雜湊、期間、假設、資格、名額、入選與排除原因、比較範圍、限制與工程確認問題。匯出文字明示研究地理範圍可能未驗證。

CSV 所有欄位加引號、雙寫內含引號；可能觸發試算表公式的前綴加單引號。JSON 的不可用觀測期間保持 `null`，`performanceIndicatorsAvailable=false`。不輸出改善百分比或合成營運資料。

## 16. 效能與靜態資料架構

官方來源 → 限定離線擷取 → 原始位元組／SHA256 → 結構與對應稽核 → 版本化快照 → 純 TypeScript 情境 → React 摘要。保留版本可重建，不在訪客端呼叫官方 API；沒有後端或資料庫。

新分頁與 CSS 延遲載入，快照在進入分頁後才取用並快取。快照 120,789 bytes；原實作量測的模組 gzip 為 17.44 kB。本次重測 58 候選、10,000 次品質情境，Node 平均 0.0105 ms；不能當成公網效能承諾。既有事故明細與 PWA 行為維持獨立。

## 17. 不支持的政策成效與因果推論

本版不估算旅行時間節省、壅塞／排放／事故減少、容量提升、公車旅客效益、號誌最佳化或道路拓寬必要性。沒有反事實、因果研究或介入前後測，名單也不是改善措施推薦。

資料就緒度不代表壅塞嚴重度；相同路名不等於相同方向或整條路涵蓋。事故與壅塞不可互作代理。

## 18. 後續資料需求與改善方向

優先取得官方研究邊界與功能性連接道路、VD／Link／Section／車道方向對照、設備版本沿革、有效取樣規格、速度／流量／占有率與 sentinel 定義、至少兩個完整工作週或其他可辯護期間及假日曆。若引入 TDX，憑證只在離線環境變數中讀取，先驗證服務配額與授權。

取得資料後重跑時間完整性、來源版本、同日參考及發布驗證，才可考慮啟用歷史模式。既有套件弱點與大型 PWA 預快取另案處理；不在此 PR 擴張至公車網路、即時監控或 Portfolio 修改。
